# DeepSeek Twenty CRM Ideal CRM Audit Review

## Decision

DeepSeek's top-level `BLOCK_RELEASE` verdict remains correct, but the supplied
supporting diagnosis is materially stale and partly self-contradictory. The
current overlay passes the complete local server integration inventory, server
units, four-shard frontend units, fresh builds, direct server typecheck, and
focused authorization regressions. Production release remains blocked by
target-environment G8 evidence, deployed extension controls, production
recovery, hosted validation, and deployment authority.

DeepSeek's `8.0/10`, `97%`, 80% E2E threshold, and three-to-five-week estimate
are not reproducible from the excerpt because no scoring rubric, coverage
denominator, staffing model, or claim-level evidence ledger is supplied.

## External calibration

Official Twenty documentation supports the control direction but does not prove
this overlay or a target deployment. Application access tokens derive from
declared roles; production logic functions default disabled and local execution
is explicitly unsandboxed; backups should be encrypted, retained, and tested.

- [Application roles and runtime tokens](https://docs.twenty.com/developers/extend/apps/config/application)
- [Self-hosted logic-function security](https://docs.twenty.com/developers/self-host/capabilities/setup)
- [Docker Compose backup and restore](https://docs.twenty.com/developers/self-host/capabilities/docker-compose)

## Recommendation

`CONDITIONAL GO` for code review and hosted validation; `NO-GO / BLOCK_RELEASE`
for deployment and release. Reproduce the sharded suite in hosted CI, conduct an
independent security review, and obtain target G8/M9/M10 evidence under separate
deployment authority before any canary or production Go/No-Go decision.
